# QSGOpacityNode：为整棵子树叠加透明度

> Qt 6.11.1 · `#include <QSGOpacityNode>` · 模块：`Qt6::Quick` · 继承：`QSGNode`

`QSGOpacityNode` 不绘制自己的像素，而是把一个透明度因子传递给全部后代。它解决的是“多个绘制节点必须作为一个整体淡入、淡出”这一场景图层级问题。

## 适用场景

自定义控件由多块几何、图片和文字构成时，把它们挂在同一个透明度节点下即可同步做过渡，无须向每种材质重复写 alpha。Qt Quick 的 `Item.opacity` 内部也是相近的概念。

透明度会沿树累乘：父节点与子节点均为 `0.5` 时，叶节点有效透明度为 `0.25`。这意味着把淡化分别加在容器和叶子上，视觉结果会比直觉更暗。

## 关键边界

只能在场景图渲染线程中读写。初始值为 `1`，`setOpacity()` 会把输入限制在 `0` 到 `1`；无须手动标记 `DirtyOpacity`，该 setter 会完成通知。

当嵌套后的有效透明度很低，渲染器可以把子树标记为 blocked 来优化，此时 `isSubtreeBlocked()` 可能返回 `true`。不要把它当成精确的“当前 opacity 是否为零”的业务判断，也不要期待被阻塞的节点继续执行 `preprocess()`。

## API 速查表

| API | 语义与边界 |
|---|---|
| `QSGOpacityNode()` | 创建透明度为 `1` 的节点。 |
| `opacity()` | 返回此节点自身的透明度因子，不是从祖先累计后的有效值。 |
| `setOpacity(qreal opacity)` | 设置透明度并限制到 `[0, 1]`；渲染器会在更新阶段把结果传播给子节点。 |
| `isSubtreeBlocked()` | 覆写基类查询；有效透明度过低时渲染器可能阻塞此子树。 |
| 继承的 `appendChildNode()` | 将要统一淡化的节点放入此节点下；子节点顺序仍决定绘制顺序。 |
