# QStack：以 QList 为底层的后进先出容器

> Qt 6.11.1 | `#include <QStack>` | 模块：`Qt6::Core` | 模板：`QStack<T>`

`QStack<T>` 在 `QList<T>` 之上提供栈的命名和操作：最后压入的元素最先取出，即 LIFO（last in, first out）。它不是一个独立存储实现，因此 `QList` 的容量、值语义、隐式共享和迭代器规则同样适用。

它适合表达“撤销步骤、括号解析、深度优先遍历、嵌套状态恢复”这类天然有栈顶概念的问题。若代码需要从头部取元素，使用 `QQueue` 或直接选择更符合业务语义的容器。

## 基本用法

```cpp
QStack<QString> undo;
undo.push("insert title");
undo.push("change color");

if (!undo.isEmpty()) {
    const QString command = undo.pop(); // "change color"
    applyUndo(command);
}
```

`push()` 把元素追加到尾部，`top()` 返回尾元素引用但不移除，`pop()` 移除并按值返回尾元素。它们分别对应 `QList::append()`、`QList::last()`、`QList::takeLast()`。

## 适合的场景

### 处理嵌套输入

解析 JSON、数学表达式或标签语言时，把尚未闭合的上下文压栈；读到关闭符号时检查并弹出栈顶。空栈一般表示输入不平衡，而不是可以继续调用 `top()` 或 `pop()` 的正常状态。

### 显式深度优先搜索

当递归深度不可控或需要暂停/恢复搜索时，用 `QStack<NodeId>` 保留待访问节点。容器存 ID 或智能指针通常优于直接存大型对象。

### 撤销记录

用一个栈存“可以撤销的命令”，另一个栈存“可以重做的命令”。执行新命令后，应清空 redo 栈，这是业务规则，不是 `QStack` 自动完成的行为。

## 值语义、生命周期与线程

`QStack` 属于 Qt 隐式共享容器，复制通常很轻量；某个副本被修改时可能发生 detach。因此：

- 复制后不要假设两个栈会继续共享同一块可修改存储。
- 对 `top()` 取得的引用，在 `push()`、`pop()`、`clear()`、`swap()` 或其他可能 detach/重分配的操作后不应继续使用。
- 元素类型必须是可赋值类型。不能把 `QWidget` 作为值存入；应存 `QWidget *`、`QPointer<QWidget>` 或其他恰当的所有权类型。
- Qt 文档说明 `QStack` 的成员函数是可重入的：不同线程操作不同实例没有问题。多个线程同时读写**同一个**实例仍需要外部同步。

容器若存原始指针，只保存指针值，不拥有对象；对象销毁策略必须由业务代码或智能指针类型表达。

## 空栈边界

`pop()` 与 `top()` 都假设栈非空。空栈上调用是违约，不应依赖调试断言、默认构造元素或偶然行为。

```cpp
while (!stack.isEmpty()) {
    consume(stack.pop());
}
```

如果“取不到元素”是正常分支，可以用 `isEmpty()` 检查，或在你的业务封装中返回 `std::optional<T>`；`QStack` 本身不提供安全的 try-pop API。

## 常见错误

1. **把 `top()` 当成弹出。** 它只返回引用，元素仍留在栈内。
2. **空栈直接 `pop()`。** 在调用前检查 `isEmpty()`。
3. **保存 `top()` 的引用后修改容器。** 后续修改可能让该引用无效。
4. **把栈当成严格受限接口。** `QStack` 继承 `QList`，调用者仍可使用 `append()`、`removeAt()` 等列表 API；团队约定需要保持 LIFO 时应自律或封装。
5. **存裸指针却误以为容器负责删除。** `QStack<T *>` 不会释放对象。

## API 速查表

| 类别 | API | 语义 | 使用边界 |
| --- | --- | --- | --- |
| 继承 | `QList<T>` 的全部 API | `QStack` 是 `QList` 的派生容器。 | 列表 API 可以绕开 LIFO 语义；是否允许要由业务约束。 |
| 压栈 | `push(const T &t)` | 复制 `t` 到栈顶。 | 等价于 `QList::append()`。 |
| 压栈 | `push(T &&t)` | 移动 `t` 到栈顶。 | Qt 6.11 起提供；移动后不要依赖参数原值。 |
| 弹栈 | `T pop()` | 移除并返回栈顶元素。 | 栈必须非空；返回值按值获得，不是引用。 |
| 查看栈顶 | `T &top()` | 返回可修改的栈顶元素引用。 | 栈必须非空；容器结构变化后引用可能失效。 |
| 查看栈顶 | `const T &top() const` | 返回只读栈顶元素引用。 | 仍要求非空，引用受容器生命周期约束。 |
| 交换 | `swap(QStack<T> &other)` | 常数时间交换两个栈的内容。 | `noexcept`；两边此前取得的元素引用都不应继续使用。 |
| 判空 | `isEmpty()`（继承） | 判断能否安全使用 `top()` / `pop()`。 | 在每一次可能弹栈的分支前检查。 |
| 清空 | `clear()`（继承） | 移除全部元素。 | 不负责删除原始指针所指对象。 |
| 容量 | `size()`（继承） | 返回当前元素数量。 | 不是容量上限，也不说明元素所有权。 |

`QStack` 的优势是把“尾部作为栈顶”的意图写进代码。它很小，但空栈前置条件、元素所有权和引用失效规则必须由使用者认真承担。
