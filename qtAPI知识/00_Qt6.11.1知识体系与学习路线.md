## 1. Qt 到底是什么

Qt 不只是一个 GUI 控件库，而是一套跨平台应用开发框架。它主要解决四类问题：

1. **统一平台差异**：用同一套 C++/QML API 面向 Windows、Linux、macOS、移动端和嵌入式平台。
2. **提供应用基础设施**：对象模型、事件循环、线程、文件、容器、时间、序列化等。
3. **提供界面技术栈**：传统桌面界面的 Qt Widgets，以及声明式界面的 Qt Quick/QML。
4. **提供专业功能模块**：网络、数据库、多媒体、图表、3D、OpenGL、打印、测试和本地化等。

可以把 Qt 理解成下面几层：

```text
你的业务代码
├─ Widgets 路线：QWidget / Layout / Model-View
├─ Quick 路线：QML / Qt Quick / Qt Quick Controls / Quick 3D
├─ 功能模块：Network / SQL / Multimedia / Charts / SVG ...
├─ 图形与窗口：Qt GUI
└─ 基础设施：Qt Core
   └─ 操作系统、窗口系统、图形 API、网络栈、数据库驱动等
```

无论最终选择 Widgets 还是 QML，`Qt Core` 都是必须掌握的基础。

## 2. Qt 程序为什么需要 QApplication 和事件循环

一个典型 Qt Widgets 程序从这里开始：

```cpp
#include <QApplication>
#include <QLabel>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    QLabel label(QStringLiteral("Hello Qt"));
    label.resize(240, 80);
    label.show();

    return app.exec();
}
```

其中三个动作非常关键：

- 构造 `QApplication`：初始化 GUI 应用所需的平台资源和全局状态。
- 调用 `show()`：让顶层窗口进入可见状态。
- 调用 `exec()`：启动事件循环，持续接收并分发鼠标、键盘、窗口、定时器和网络等事件。

如果没有事件循环，程序执行完 `main()` 就退出，窗口也无法持续响应用户输入。

对于没有图形界面的程序，通常使用 `QCoreApplication`；需要图形能力但不使用 Widgets 时，可以使用 `QGuiApplication`：

```text
QCoreApplication
  └─ QGuiApplication
       └─ QApplication
```

选择原则：使用满足需求的最小类型，不要在纯命令行服务中无缘无故使用 `QApplication`。

## 3. Qt 最核心的对象模型：QObject

`QObject` 是 Qt 对象系统的中心。许多 Qt 类直接或间接继承它，并获得以下能力：

- 父子对象所有权
- 信号与槽
- 事件系统
- 动态属性
- 运行时类型信息和元对象系统
- 国际化相关支持
- 对象线程归属

### 3.1 父子对象与自动销毁

```cpp
auto *window = new QWidget;
auto *button = new QPushButton(QStringLiteral("确定"), window);

delete window; // button 会随父对象 window 一起被销毁
```

`QObject` 的父对象销毁时，会销毁其子对象。这个机制减少了手动 `delete`，但必须分清两类关系：

- **对象所有权**：由 `QObject::parent()` 决定谁负责销毁。
- **C++ 变量作用域**：栈对象在离开作用域时自动析构。

不要把有父对象的栈对象设置成一个生命周期更短或销毁顺序不正确的父对象，否则可能造成重复销毁。

### 3.2 信号与槽

信号表示“某件事发生了”，槽或普通可调用对象表示“如何响应”：

```cpp
auto *button = new QPushButton(QStringLiteral("关闭"), &window);

QObject::connect(button, &QPushButton::clicked,
                 &window, &QWidget::close);
```

现代 Qt C++ 推荐函数指针语法，因为编译器能够检查参数类型。信号与槽可以是直接调用，也可以跨线程排队执行；具体行为由连接类型和对象的线程归属决定。

### 3.3 元对象系统

自定义 `QObject` 子类若要声明信号、槽、属性或使用完整的运行时元信息，一般需要 `Q_OBJECT`：

```cpp
class Counter : public QObject
{
    Q_OBJECT

public:
    using QObject::QObject;

signals:
    void valueChanged(int value);
};
```

CMake 的 `AUTOMOC` 或 `qt_add_executable()` 会调用元对象编译器 `moc`，生成额外 C++ 代码。`Q_OBJECT` 不是普通宏展开就能完成的功能。

## 4. Qt 的两条界面路线

### 4.1 Qt Widgets

Widgets 是成熟的 C++ 桌面界面技术栈，适合：

- 传统桌面软件
- 管理工具、编辑器、IDE 类应用
- 表单和数据密集型界面
- 需要大量原生桌面控件的项目

核心知识链：

```text
QWidget
→ 常用控件
→ Layout 布局管理
→ 事件与绘制
→ Main Window 框架
→ Model/View
→ 样式、委托和自定义控件
```

最小布局示例：

```cpp
QWidget window;
auto *layout = new QVBoxLayout(&window);
layout->addWidget(new QLabel(QStringLiteral("用户名：")));
layout->addWidget(new QLineEdit);
layout->addWidget(new QPushButton(QStringLiteral("登录")));
window.show();
```

界面大小应主要交给布局管理器，不应依赖大量固定坐标。

### 4.2 Qt Quick 与 QML

Qt Quick 使用 QML 声明界面结构，以 JavaScript 表达轻量逻辑，并可与 C++ 后端结合。它适合：

- 动画和视觉效果较多的界面
- 触控、移动端和嵌入式界面
- 需要快速迭代视觉表现的项目
- 2D/3D 混合界面

最小 QML 示例：

```qml
import QtQuick
import QtQuick.Controls

ApplicationWindow {
    width: 360
    height: 180
    visible: true
    title: "Qt Quick 示例"

    Button {
        anchors.centerIn: parent
        text: "确定"
        onClicked: console.log("clicked")
    }
}
```

核心知识链：

```text
QML 对象与属性绑定
→ Item、锚点与布局
→ 信号处理
→ Qt Quick Controls
→ Model/View
→ 动画与状态
→ C++/QML 集成
→ 场景图、性能与部署
```

### 4.3 应该选择哪一条路线

| 需求 | 更合适的选择 |
|---|---|
| 传统桌面工具、复杂表格和树 | Qt Widgets |
| 动画、触控、自定义视觉界面 | Qt Quick/QML |
| 成熟的纯 C++ 桌面项目 | Qt Widgets |
| 设计人员需要参与界面实现 | Qt Quick/QML |
| 在 Widgets 中嵌入少量 QML | `QQuickWidget`，但要评估渲染成本 |
| 在 QML 中复用 C++ 业务层 | 注册 C++ 类型或暴露上下文对象 |

两条路线可以共享 C++ 业务层，但不应在没有必要时随意混合两套界面体系。

## 5. 构建系统：CMake、Qt 模块和目标

Qt 6 推荐使用 CMake。一个 Widgets 项目的基础配置如下：

```cmake
cmake_minimum_required(VERSION 3.21)
project(MyApp LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(Qt6 REQUIRED COMPONENTS Widgets)

qt_add_executable(MyApp
    main.cpp
)

target_link_libraries(MyApp PRIVATE Qt6::Widgets)
```

理解三点：

1. `find_package` 查找指定 Qt 模块及其 CMake 配置。
2. `qt_add_executable` 创建程序目标，并接入 Qt 所需的构建处理。
3. `target_link_libraries` 声明程序真正依赖的 Qt 目标。

增加网络功能时，应同时修改查找和链接：

```cmake
find_package(Qt6 REQUIRED COMPONENTS Widgets Network)
target_link_libraries(MyApp PRIVATE Qt6::Widgets Qt6::Network)
```

`qmake` 仍存在于文档和旧项目中，但新 Qt 6 项目优先选择 CMake。

## 6. 贯穿所有模块的关键概念

### 6.1 隐式共享与写时复制

许多 Qt 值类型，例如 `QString`、`QByteArray`、`QImage`，使用隐式共享。复制对象通常只增加共享数据的引用计数；真正修改时才复制底层数据。

```cpp
QString a = QStringLiteral("Qt");
QString b = a;  // 通常共享底层数据
b.append('6');  // 修改时分离
```

这让按值传递比直觉中更便宜，但仍应根据 API 语义合理使用 `const T &`、移动语义和返回值优化。

### 6.2 值对象与 QObject 对象

- `QString`、`QSize`、`QRect` 等通常是可复制的值对象。
- `QObject` 及其子类通常不可复制，以指针和父子所有权管理。

不要试图把 `QObject` 子类当普通值类型放入需要复制的容器；需要长期引用时，还要考虑对象可能被外部销毁，可使用 `QPointer<T>` 观察其生命周期。

### 6.3 事件驱动与异步操作

GUI 线程的事件循环必须保持畅通。耗时操作如果直接在按钮槽函数里运行，会让窗口无法重绘和响应：

```cpp
// 错误思路：在 GUI 线程中执行长时间计算
connect(button, &QPushButton::clicked, this, [this] {
    doHeavyWork();
});
```

正确方向包括：

- 使用异步 API，例如 `QNetworkAccessManager`。
- 使用 `Qt Concurrent` 执行适合并行化的工作。
- 使用工作对象配合 `QThread`。
- 将任务拆成小步，通过事件循环调度。

不要为了“保持响应”而到处调用 `QCoreApplication::processEvents()`；它可能引入重入和难以分析的状态问题。

### 6.4 线程归属

`QObject` 有线程归属（thread affinity）。排队信号和事件会在接收对象所属线程处理。一般规则：

- GUI 对象只能在 GUI 线程创建和操作。
- 不要直接从工作线程修改控件。
- 跨线程传递数据优先使用信号与槽。
- `moveToThread()` 移动的是对象的线程归属，不是立即执行某个成员函数。

### 6.5 坐标、尺寸和高 DPI

Qt 6 默认面向高 DPI。界面布局应使用逻辑像素和布局约束，不应假设一个像素永远对应一个物理屏幕像素。图片、图标和自绘内容需要考虑设备像素比。

## 8. 推荐的由浅入深学习路线

### 阶段一：能写出结构正确的小程序

学习内容：

1. CMake 项目结构
2. `QCoreApplication` / `QApplication`
3. `QObject`、父子所有权、信号与槽
4. `QString`、容器、日期时间、文件 I/O
5. Widgets 或 QML 二选一完成基础界面

完成标准：能解释对象由谁销毁，能让界面自适应大小，能用信号与槽连接交互。

### 阶段二：掌握实际应用的组织方式

学习内容：

1. 事件系统与自定义事件
2. Model/View 数据展示
3. 网络请求与 JSON
4. 数据库读写
5. 资源系统、配置、日志和国际化
6. 单元测试

完成标准：能将界面、业务逻辑和数据访问分开，不把所有代码堆进一个窗口类。

### 阶段三：异步、线程与性能

学习内容：

1. GUI 线程限制
2. `QThread` 工作对象模式
3. `QtConcurrent` 与 `QFuture`
4. 异步网络和取消操作
5. 对象生命周期与跨线程信号
6. 性能测量，而不是凭感觉优化

完成标准：耗时任务不阻塞界面，退出应用时不会残留线程或访问已销毁对象。

### 阶段四：高级界面和平台能力

Widgets 路线继续学习自定义绘制、代理、样式、Graphics View；Quick 路线继续学习场景图、动画、C++ 集成和性能。按项目需要再进入 Multimedia、Charts、OpenGL、Quick 3D、打印等专业模块。

## 9. API 文档应该怎样读

遇到一个新类时，建议按以下顺序阅读：

1. **一句话简介**：它解决什么问题。
2. **继承关系**：它从父类获得了什么能力。
3. **Header 和 CMake**：如何正确引入和链接。
4. **Detailed Description**：类的设计模型、约束和推荐用法。
5. **构造函数与工厂函数**：如何创建。
6. **属性、普通函数、信号与槽**：如何配置和交互。
7. **所有权与线程说明**：谁销毁对象、在哪个线程调用。
8. **相关类与示例**：它在整个模块中的位置。

不要只根据函数名试错。Qt 文档中的详细说明经常包含线程限制、所有权转移、同步/异步语义和平台差异，这些才是错误最常出现的地方。

## 10. 一个完整功能应该怎样拆解

以“从网络下载 JSON 并显示列表”为例，涉及的知识并不只属于一个控件：

```text
QApplication / 事件循环
        ↓
QNetworkAccessManager 异步请求
        ↓
QNetworkReply 完成信号、错误与生命周期
        ↓
QJsonDocument / QJsonObject / QJsonArray 解析
        ↓
业务数据模型
        ↓
QAbstractListModel
        ↓
QListView（Widgets）或 ListView（QML）
```

这也是为什么要先建立模块关系，再学习单个类。单个 API 会用不等于能够设计稳定的 Qt 应用。

## 11. 常见学习误区

### 11.1 只背 API，不理解事件循环

这会导致阻塞界面、错误处理异步结果，以及在对象销毁后继续回调。

### 11.2 把父对象当成普通指针参数

Qt 构造函数中的 `parent` 往往代表所有权，而不仅是视觉层级。必须知道父对象何时销毁。

### 11.3 在工作线程直接操作控件

GUI 控件应留在 GUI 线程。工作线程通过信号返回数据，由 GUI 线程更新界面。

### 11.4 使用固定坐标搭界面

固定坐标很难适应字体、DPI、窗口大小和翻译文本。Widgets 使用布局，Quick 使用 anchors 或 Layouts。

### 11.5 过早进入私有或平台集成 API

先掌握稳定的公共 API。名字中带 private、平台集成或实验性标记的接口可能在小版本间变化。

### 11.6 示例能运行就认为设计正确

最小示例通常省略架构、错误恢复、取消、资源清理和测试。应区分“演示一个 API”和“生产代码结构”。

---

## 总结

学习 Qt 的正确顺序不是“把所有类背一遍”，而是先掌握 `Qt Core` 提供的对象、事件和异步模型，再选择 Widgets 或 Qt Quick 作为界面主线，随后按项目需求引入 Network、SQL、Multimedia 等模块。具体 API 必须放回事件循环、对象所有权、线程归属和模块依赖中理解，才能从“示例能运行”走到“应用可维护”。
