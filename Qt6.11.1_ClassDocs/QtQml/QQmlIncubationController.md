# QQmlIncubationController

> Qt 6.11.1 · Qt Qml

## 1. 先建立直觉

**一句话定位：** `QQmlIncubationController` 是 QML 属性绑定与场景图机制 中的类型，负责把这一机制中的数据、状态或资源交给其他 Qt 对象使用。

**模块背景：** 这是 Qt Qml 模块中的公开 C++ API，具体职责以类摘要和继承关系为准。

### 这是什么

`QQmlIncubationController` 是 Qt Quick/QML 体系中的公开类型，连接 C++ 对象、QML 属性绑定和场景图渲染。

**内部模型：** QML 属性绑定是声明式依赖关系，C++ 侧的属性、信号和对象生命周期会直接影响绑定是否更新。涉及渲染线程的类型不能随意在 GUI 线程之外操作。

**适用场景：** 需要 QML 界面、动画、场景图或把 C++ 数据暴露给 QML 时使用。

**典型调用链：** 注册/创建类型 -> 暴露 properties/signals/invokables -> QML 创建和绑定 -> 在 C++ 中通过信号更新状态 -> 按线程规则处理渲染资源。

**先记住的坑：** 不要在 QML 绑定中产生副作用；注意 QObject 所有权；区分 GUI 线程和 render thread；注册类型版本要稳定。

### 工作机制

QML 属性绑定是声明式依赖关系，C++ 侧的属性、信号和对象生命周期会直接影响绑定是否更新。涉及渲染线程的类型不能随意在 GUI 线程之外操作。

### 状态、生命周期和线程

**生命周期：** QML 引擎、上下文和对象所有权必须明确。由 QML 创建的对象通常由引擎管理；通过 context property 或 C++ 暴露的对象要决定由 C++ 持有还是转移给 QML，不能让绑定指向悬空对象。

**状态与结果：** 属性绑定和直接赋值不是一回事：直接给被绑定属性赋值通常会打破原有绑定。C++ 属性要有正确的 notify signal，QML 才能在数据变化时更新；信号参数和属性当前值要保持一致。

**线程与事件循环：** 大多数 QML 对象和 GUI 操作在 GUI 线程，场景图渲染还可能在 render thread。不要在渲染阶段调用 GUI 对象 API；后台数据通过线程安全的信号/槽边界送入 QML。

## 5. API 逐个说明

本节依据 Qt 6.11.1 原始类页逐项整理。每个条目先说明它实际解决的问题，再说明调用方式、返回结果和容易忽略的限制；不再用函数名拆词猜测用途。

### `QQmlIncubationController::QQmlIncubationController()`

**作用与语义：**

创建一个新的孵化控制器。

### `QQmlEngine *QQmlIncubationController::engine() const`

**作用与语义：**

返回孵化控制器被设置为开启的`QQmlEngine`，或者如果没有在任何引擎上设置，则返回0。

### `void QQmlIncubationController::incubateFor(int msecs)`

**作用与语义：**

孵化物体直到`msecs`，或者直到没有更多可孵化的物体为止。

### `void QQmlIncubationController::incubateWhile(std::atomic<bool> *flag, int msecs = 0)`

**作用与语义：**

在`flag`指向的原子布尔为真时孵化物体，或直到没有更多可孵化对象，或如果 `msecs` 不是零，则最多可孵化`msecs`。
通常，这种方法与线程或UNIX信号结合使用，该信号在需要中断孵化时将`flag`指向的布尔设置为false。
注意：`flag`是通过获取内存排序读取的。

### `int QQmlIncubationController::incubatingObjectCount() const`

**作用与语义：**

返回当前孵化中的物体数量。

### `[virtual protected] void QQmlIncubationController::incubatingObjectCountChanged(int incubatingObjectCount)`

**作用与语义：**

当孵化对象数量发生变化时调用。`incubatingObjectCount` 是新的孵化对象数量。 默认实现不执行任何操作。
