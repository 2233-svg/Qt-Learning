# QHideEvent

> Qt 6.11.1 · Qt GUI · 来自 `QHideEvent`

## 1. 先建立直觉

`QHideEvent` 表示控件或窗口离开可见状态。它可能由 `hide()`、父控件隐藏、窗口最小化相关流程或关闭流程触发。隐藏不等于销毁，对象通常仍然存在，之后可以再次显示。

因此，`hideEvent()` 适合做“不可见时不应继续消耗资源”的处理，例如暂停视频预览、停止刷新定时器、收起临时提示；不适合放只能执行一次的永久清理。

## 2. 类说明

`QHideEvent` 继承自 `QEvent`，自身只有默认构造函数。Widgets 中通常通过 `QWidget::hideEvent()` 接收，也可以在 `event()` 中处理 `QEvent::Hide`。

类说明只用于表明这个事件类型来自 `QHideEvent`。事件不携带隐藏原因，需要结合控件状态、窗口状态和业务流程判断。

## 3. API 速查

| API | 用途速查 |
| --- | --- |
| `QHideEvent()` | 构造隐藏事件，主要用于测试或自定义事件投递。 |
| `accept()` / `ignore()` | 继承自 `QEvent`，设置接受状态；通常不能靠它可靠阻止隐藏。 |
| `type()` | 继承自 `QEvent`，隐藏事件通常为 `QEvent::Hide`。 |

## 4. 关键用法

### 隐藏时暂停高频任务

```cpp
void VideoPreview::hideEvent(QHideEvent *event)
{
    m_refreshTimer.stop();
    m_renderer.pause();
    QWidget::hideEvent(event);
}

void VideoPreview::showEvent(QShowEvent *event)
{
    QWidget::showEvent(event);
    m_renderer.resume();
    m_refreshTimer.start();
}
```

如果窗口隐藏后仍然不断刷新纹理或请求数据，后台负载会在用户看不到时继续增长。

### 隐藏不应清空用户状态

面板隐藏后再次显示，通常应恢复筛选条件、滚动位置、选区和输入内容。只有临时对象或敏感数据才需要在隐藏时清除。

### 关闭流程可能包含隐藏

如果窗口设置了 `WA_DeleteOnClose`，关闭后隐藏事件可能只是销毁前的生命周期步骤。需要永久释放的资源应放在明确的停止流程或析构函数中，而不是只依赖 `hideEvent()`。

## 5. 使用场景

`QHideEvent` 适合视频、音频可视化、实时图表、地图瓦片、远程桌面画面、动画面板和临时浮层。不可见时暂停工作，重新可见时恢复，是节省资源和减少后台噪声的常见策略。

它也适合保存界面快照。停靠面板、工具箱和浮动窗口可以在隐藏前记录几何状态，在下一次显示时恢复。

## 6. 常见坑与经验

不要把 `hideEvent()` 当作析构函数。控件通常仍然存在，信号连接、模型引用和用户状态都应保留。

不要在隐藏事件中无条件删除子控件。反复打开面板会变成不断创建和销毁，状态也难以恢复。

不要依赖 `ignore()` 阻止隐藏。需要阻止用户关闭或切换的逻辑，应在上层状态机或关闭事件中处理。

不要暂停任务却忘了在 `showEvent()` 恢复，容易出现“面板重新显示但数据不再更新”的假死。

## 7. 知识点覆盖
